# truyenAI — Hệ thống sản xuất truyện bằng AI (MVP) Implementation Plan

> **For Hermes:** Execute task-by-task, commit after each task. UI + prompts + nội dung: TIẾNG VIỆT.

**Goal:** Web app tự động viết truyện hoàn chỉnh từ 1 prompt mô tả (thể loại, nhân vật, bối cảnh, số chương...): Next.js dashboard + FastAPI backend + AI agent đa giai đoạn + Postgres + Redis worker + SSE.

**Architecture:** Monorepo `backend/` (FastAPI, SQLAlchemy async, arq worker, httpx gọi LLM OpenAI-compatible) + `frontend/` (Next.js 15 App Router, Tailwind v4, React Query). Postgres + Redis chạy Docker. Worker chạy pipeline 7 giai đoạn, checkpoint từng bước vào DB, phát event qua Redis pub/sub → SSE ra dashboard.

**Tech Stack:** Python 3.12 (uv), FastAPI, SQLAlchemy 2 async + asyncpg, arq, httpx, Pydantic v2 | Next.js 15, React Query, Tailwind v4 | Postgres 16, Redis 7 | Gemini OpenAI-compatible (`https://generativelanguage.googleapis.com/v1beta/openai`, model `gemini-2.5-flash`), key trong `.env` — KHÔNG bao giờ hỏi key trong chat. Không có key ⇒ MockLLM chạy full pipeline.

## Quyết định đã chốt với user
- LLM: **Gemini** qua OpenAI-compatible endpoint (env `LLM_BASE_URL`, `LLM_API_KEY`, `LLM_MODEL`).
- UI + nội dung truyện mặc định: **tiếng Việt** (locale vi-VN).
- Phạm vi: **Full MVP** — compose, worker, SSE, editor, tests, e2e dry-run.

## Ports (tránh đụng docker film stack)
- web 3000, api 8000; postgres host **54329** (container 5432), redis host **63790** (container 6379).

## Data model (backend/migrations/001_init.sql)
- `projects(id uuid pk, title, prompt text, options jsonb, status, created_at, updated_at)` — status: `draft|queued|running|completed|failed|cancelled`
- `story_bible(project_id pk fk, premise, genre, style, world jsonb, facts jsonb)` — facts = mảng "sự kiện đã thiết lập" để kiểm tra mạch truyện
- `characters(id, project_id fk, name, role, description, arc jsonb)`
- `outline(id, project_id fk, chapter_number, title, summary, beats jsonb)`
- `chapters(id, project_id fk, chapter_number, title, content, summary, status, word_count, updated_at)` — status: `pending|draft|reviewed|revised|final`
- `revisions(id, chapter_id fk, revision_no, content, review jsonb, created_at)`
- `jobs(id uuid pk, project_id fk, type, status, stage, error, created_at, updated_at)` — status: `queued|running|done|failed|cancelled`
- `agent_steps(id, job_id fk, project_id, stage, ref int null, status, created_at)` — checkpoint resume; `UNIQUE(job_id, stage, ref)`
- `agent_events(id, project_id, job_id, type, payload jsonb, created_at)` — lịch sử event (replay khi load trang)

## Pipeline agent (backend/app/agent/)
1. `analyze` — prompt → spec JSON có cấu trúc (thể loại, bối cảnh, nhân vật đề xuất, phong cách, số chương).
2. `outline` — mảng chương: title + summary + beats (JSON).
3. `bible` — story bible + character sheets (JSON) → bảng `story_bible`, `characters`.
4. `chapter N` — viết chương từ bible + outline + tóm tắt các chương trước (context giới hạn, không bùng nổ token). Lưu `summary` ~120 từ.
5. `review N` — rà consistency vs bible/outline/chương trước → JSON `{issues:[], verdict: pass|revise}`; verdict=revise ⇒ viết lại tối đa 2 vòng, lưu revision.
6. Sau chương cuối: `finalize` — kiểm tra kết truyện khớp yêu cầu, tổng kết.
- State machine enum `Stage`, `canTransition`, checkpoint ghi `agent_steps`; resume = bỏ qua step `completed`. Giữa các stage check `job.status == cancelled` để hủy.

## Event/SSE
- Worker publish Redis channel `job:{id}`: `{type, payload}` (`stage_started|stage_completed|chapter_draft|chapter_review|log|job_done|job_failed`) + persist `agent_events`.
- `GET /api/projects/{id}/events` — SSE: replay event cũ từ DB rồi subscribe Redis.

## API (backend/app/routers/)
- `POST /api/projects` {title, prompt, options} → tạo project + enqueue job
- `GET /api/projects`, `GET /api/projects/{id}` (kèm bible, characters, outline, chapters meta, job progress)
- `POST /api/projects/{id}/run` (start/resume/retry), `POST /api/projects/{id}/cancel`
- `GET /api/projects/{id}/chapters`, `GET/PUT /api/projects/{id}/chapters/{n}` (PUT = sửa tay ⇒ revision mới)
- `GET /api/projects/{id}/chapters/{n}/revisions`
- `GET /api/projects/{id}/events` (SSE), `GET /api/health`

## Verification
- `make test` — pytest xanh (cần compose db).
- `make e2e` — project tạo được, pipeline chạy xong với MockLLM, SSE có event, chapters có nội dung + revisions.
- `docker compose up -d` → http://localhost:3000 dùng được (thêm project, xem progress, sửa chương).
- Gemini thật: user tự điền `LLM_API_KEY` vào `.env`, restart — không test key trong chat.

## Risks
- Python 3.14 ecosystem ⇒ pin 3.12 bằng uv (`.python-version`).
- Next.js standalone build trong Docker cần `output: 'standalone'`.
- SSE qua Next dev proxy hay dính cache ⇒ frontend gọi thẳng API_URL, không proxy.
- Gemini free-tier rate limit ⇒ worker retry nhẹ + giới hạn concurrency 1 job.
